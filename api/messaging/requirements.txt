# requirements.txt — messaging app
#
# This package ships with no pinned dependencies at all, which is a real
# deployment risk on its own: an unconstrained `pip install` can silently
# resolve a Django/DRF combination that has never been run together.
# Concretely confirmed during audit:
#   - models.py's CheckConstraint(check=...) works on all Django versions
#     (Django 5.0 only understands the older `check=` keyword).
#   - Django 6.1 removes django.utils.cache.cc_delim_re, which the
#     currently-released djangorestframework (3.17.x) still imports at
#     module load — installing Django 6.1 breaks `import rest_framework`
#     entirely, before any of this app's own code even runs.
# Floors below are what this audit actually ran the full test suite and a
# real PostgreSQL 16 migration against — treat them as a verified
# baseline, not an arbitrary minimum. Merge with your host project's own
# requirements.txt (earning_backend) rather than replacing it; `>=`
# floors compose fine with an existing file, unlike hard `==` pins.
